# Documentation screenshots

These are captures of the actual Scope windows, taken on 3 November 2026 with
macOS 27.2 and Xcode 27.2. Both builds use merged source at
[`78c35b6`](https://github.com/antonisPanos/scope/commit/78c35b6daf6aaf7302e89b9b940284c385b3faa3),
which includes [#139](https://github.com/antonisPanos/scope/pull/139) and
[#140](https://github.com/antonisPanos/scope/pull/140). That source follows v0.3.0;
the browser changes are included for the v0.4.0 release.

## Content and privacy

All visible documents and illustrations belong to a fictional **Aegean Studio**
project made for this documentation. The artwork is original procedural coastal
illustration; the presentation, brief, budget and 120-item seasonal catalog are
disposable fixtures. No personal documents, photographs, tags or mounted volumes
were used as demo content. The sidebar and path bar are hidden in captures to
avoid exposing personal locations. These are app windows, not isolated test widgets.

Fixtures lived only under `~/ScopeScratch/Scope-Docs-Demo-20261103`. File-changing
UI QA used Scope Dev: compressing the demo artwork created a ZIP in that folder.
Production Scope was used only for read-only Gallery and Columns captures. The
owned fixtures and temporary builds are removed after the work is pushed; these
intentional documentation images remain in Git.

## Capture workflow

1. Build both schemes from the intended merged source, using command-local signing
   overrides where needed. Never change the production/development path policies.
2. Create fresh, named demo fixtures beneath `~/ScopeScratch`; tag only those files.
   Use enough entries to demonstrate scrolling and realistic mixed file types.
3. Browse in Scope Dev, set the view, and wait for listings/thumbnails/search results.
   `scripts/devhook.swift` can select demo items, run commands, switch appearance,
   and save PNGs in the temporary folder. See [AGENTS.md](../../AGENTS.md).
4. Inspect native windows as well: bitmap snapshots can omit remote Quick Look
   previews and sidebar vibrancy. Icons uses native Scope Dev captures; Gallery and Columns use native production
   captures. The remaining Scope Dev images use the main browser-window bitmap.
   For this session only, the snapshot hook selected the main window rather than
   a visible system window-sharing child; that capture-only change was restored
   and is not part of the documentation commit.
5. Review every image for private content, correct toolbar state, complete previews,
   clipping and accurate captions. Check light/dark Markdown rendering. Keep only
   the intended assets, and clean up only resources owned by the capture session.

The screenshots preserve the actual app rendering; there are no composited file
lists, injected fake operation states or edited feature controls.
